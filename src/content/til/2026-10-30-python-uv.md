今日はPythonのuvについて詳しくなりたい。
実務で使うものの、コマンドしか理解していないので、説明できるようになりたい。

## uvとは何か

まずuvとはPythonのパッケージマネージャである。
uvはOSSなので、GitHubからREADMEを見ると、
https://github.com/astral-sh/uv

> A single tool to replace pip, pip-tools, pipx, poetry, pyenv, twine, virtualenv, and more.

なるほど、これまで使われてきた周辺のツールを色々まとめた物なのか

- pip：パッケージマネージャ
- pip-tools：依存関係のロック
- poetry：プロジェクト管理ツール
- pyenv：Python本体のバージョン管理

この辺りは見慣れないので適当だけど、、

- pipx：Python製CLIのスタンドアロンインストーラー、コマンド毎の専用の実行環境を作ってくれるみたい
- twine：ビルド済みのパッケージをPyPIに配布
- virtualenv：仮想環境

パッケージマネージャと言いつつ、全セットみたいなイメージ

uvはインストールした後だけど、早速プロジェクトの初期化から

```console
$ uv init --bare --no-workspace

Initialized project `lockfile`
```

`pyproject.toml`が作成された

```console
$ uv add pytest

Using CPython 3.12.12
Creating virtual environment at: .venv
Resolved 7 packages in 190ms
Prepared 4 packages in 197ms
Installed 5 packages in 14ms
 + iniconfig==2.3.1
 + packaging==26.3
 + pluggy==1.7.0
 + pygments==2.21.0
 + pytest==9.2.0
```

`.venv`と`uv.lock`が作成された

```console
$ uv tree

Resolved 7 packages in 30ms
lockfile v0.1.0
└── pytest v9.2.0
    ├── iniconfig v2.3.1
    ├── packaging v26.3
    ├── pluggy v1.7.0
    └── pygments v2.21.0
```

どのパッケージに何が依存しているかわかった

なんか`uv add`したら、色々作られてたけど、何が起きた

`uv add`の実行順序を整理すると

1. `pyproject.toml`に追加
2. `uv.lock`に追加
3. `.venv`がなければ作成とインストール

依存関係をコントロールできるファイルを作成、そこから依存関係をロックする
仮想環境を作成して、ロックしたバージョンをインストールすると言う流れかな

## なぜuvはactivateしなくていいのか

**Python標準のvenv**

```console
$ python3 -m venv std-venv && cat std-venv/bin/activate

export VIRTUAL_ENV=/Users/user_name/Documents/training/uv-pip-venv/std-venv
PATH="$VIRTUAL_ENV/"bin":$PATH"
export PATH
```

**uvのvenv**

```console
$ uv venv uv-venv && cat uv-venv/bin/activate

VIRTUAL_ENV='/Users/user_name/Documents/training/uv-pip-venv/uv-venv'
PATH="$VIRTUAL_ENV/bin:$PATH"
export PATH
```

「Python標準のvenv」と「uvのvenv」を見比べてみた。ほとんど同じ
pathは一部省略するけど、シェルスクリプトで書いていて、環境変数のPATHを書き換えている。
だから、`venv`配下のPythonを使いますよ、とただPATHを通すだけ。
ちなみに、`venv/bin/python`はただのシンボリックリンクらしく、実体は別の場所にある。

そういえば`activate`って不要なのかな？
いつも`source .venv/bin/activate`こういうの打っていて
Pythonとライブラリを各プロジェクトやまとまり毎に異なった環境に出来るぐらいのイメージだった。

さっき作成した`experiments/lockfile` の中で実験してみる。

```console
$ cd experiments/lockfile

$ python3 -c 'import pytest'
Traceback (most recent call last):
  File "<string>", line 1, in <module>
    import pytest
ModuleNotFoundError: No module named 'pytest'. Did you mean: 'test'?

$ uv run python -c 'import pytest; print(pytest.__file__)'
/Users/user_name/Documents/training/uv-pip-venv/experiments/lockfile/.venv/lib/python3.12/site-packages/pytest/__init__.py
```

次は`uv run`の中身を確認
`sources/uv/crates/uv-project-commands/src/run.rs`

```rust
process.env(EnvVars::PATH, new_path);

// Ensure `VIRTUAL_ENV` is set.
if interpreter.is_virtualenv() {
    process.env(EnvVars::VIRTUAL_ENV, interpreter.sys_prefix().as_os_str());
}
```

activateがシェル全体に対してしていた PATH と VIRTUAL_ENV の設定を、uv run は起動するコマンドにだけしている

## Pythonそのものは何？

PATHを通して、`.venv/bin/python`を使うとして、pythonそのものって何？
深追いすると大変そうだけど、、

毎回バージョン違いをインストールしてきているけど、そんなに軽量なのかな。
https://github.com/python/cpython
これがPython本体、C言語で書かれている。

構文解析とルールが大量に書いてあるはず、実感を得るためにif文でも探してみる
`Grammar/python.gram`

```text
# If statement
# ------------
if_stmt[stmt_ty]:
    | invalid_if_stmt
    | 'if' a=named_expression ':' b=block c=elif_stmt {
        _PyAST_If(a, b, CHECK(asdl_stmt_seq*, _PyPegen_singleton_seq(p, c)), EXTRA) }
    | 'if' a=named_expression ':' b=block c=[else_block] { _PyAST_If(a, b, c, EXTRA) }
elif_stmt[stmt_ty]:
    | invalid_elif_stmt
    | 'elif' a=named_expression ':' b=block c=elif_stmt {
        _PyAST_If(a, b, CHECK(asdl_stmt_seq*, _PyPegen_singleton_seq(p, c)), EXTRA) }
    | 'elif' a=named_expression ':' b=block c=[else_block] { _PyAST_If(a, b, c, EXTRA) }
else_block[asdl_stmt_seq*]:
    | invalid_else_stmt
    | 'else' &&':' b=block { b }

# While statement
```

これは書き方の定義だけで、命令は別の場所にあるけど、イメージは湧く。

ちなみにCPython以外にJavaで書かれたJythonもあるらしく、python=プログラミング言語と何となく捉えていたけど、厳密に言うと言語ルールなので、別の言語で書いても決まり事さえ合っていればOK

uvがインストールしているのはpython-build-standaloneがビルドしたCPython
https://github.com/astral-sh/python-build-standalone

ビルドについても詳しく理解したいけど、機械語に変換された後ぐらいの認識
